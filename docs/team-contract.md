# Правила взаимодействия в команде «Лампочка»

## 1. Основной канал коммуникации
* Основная оперативная и проектная связь осуществляется в общем чате команды в социальной сети VK.
* Для обсуждений, требующих фиксации результатов и решений, используются темы/треды в рабочем чате.
* Хранение всех официальных отчетов, документации, макетов и кода выполняется строго в командном репозитории GitHub (team-лампочка-project).

## 2. Порядок обсуждения задач и принятия решений
* Обсуждение задач: Все текущие вопросы и архитектурные решения выносятся на обсуждение в общий чат VK.
* Принятие решений:
  * Технические и архитектурные решения принимаются Архитектором ПО (Кирюхина К.) с учетом мнения Программиста (Лайкевич А.).
  * Финальное утверждение сроков, приоритетов и общего вектора проекта остается за Руководителем разработки (Макаров М.).
  * В случае разногласий решение принимается путем открытого голосования участников команды. При равенстве голосов решающим является голос Руководителя разработки.

## 3. Соблюдение сроков и дедлайнов
* Сроки выполнения этапов и сдачи практических работ устанавливаются Руководителем разработки на основе общего учебного плана.
* Каждая задача или практическая работа должна быть зафиксирована в репозитории через Pull Request (PR) не позднее чем за 24 часа до наступления официального дедлайна.
* При возникновении форс-мажорных обстоятельств или задержек участник обязан уведомить команду в чате VK заранее (не менее чем за 12 часов до дедлайна).

## 4. Порядок работы с Git и отчетами
* Запрещается отправлять изменения непосредственно в ветку main.
* Все изменения вносятся в отдельной ветке (feature/<имя_участника> или role/<название_роли>).
* Перед слиянием ветки обязателен этап перекрестного проверки (Code Review / Report Review) и создание Pull Request.
* Сообщения к коммитам должны быть осмысленными и отражать суть внесенных изменений (например, feat: добавил отчет по роли архитектора).
